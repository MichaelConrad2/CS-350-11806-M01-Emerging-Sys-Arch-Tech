# CS 350 – Emerging Systems Architectures and Technologies

## Module Eight Portfolio Submission

### Project Overview

This repository contains my coursework and project artifacts from CS 350: Emerging Systems Architectures and Technologies. Throughout this course, I gained hands-on experience working with embedded systems, programming hardware components, and understanding how software interacts with physical devices.

The main project involved developing a thermostat system using a Raspberry Pi and Python. The purpose of the project was to create a functional embedded system capable of monitoring temperature, responding to user inputs, and controlling hardware components based on different operating modes.

The thermostat system was designed to support heating, cooling, and off modes. It used LEDs to indicate the current operating state, buttons for user input, and an LCD to display system information. A state machine was implemented to manage transitions between operating modes and ensure the system responded appropriately to different conditions.

This project helped demonstrate how software can be used to control hardware while considering system performance, reliability, and maintainability.

## Portfolio Artifacts

The two artifacts selected for this portfolio are:

**Artifact One: Thermostat Python Source Code**

This artifact demonstrates my ability to develop software that interacts with hardware components. It includes the programming logic used to control the thermostat, process user inputs, manage operating states, and communicate with connected devices.

**Artifact Two: Thermostat State Machine and System Design**

Together, these artifacts demonstrate my ability to develop embedded software, understand hardware interactions, and apply programming concepts to practical problems.

## Project Reflection

### 1. Summarize the project and what problem it was solving.

The goal of this project was to develop an embedded thermostat system using a Raspberry Pi. The system needed to monitor temperature, respond to button inputs, and provide visual feedback through LEDs and an LCD display.

The main challenge was getting the hardware and software to work together correctly. Unlike traditional software projects, embedded systems require the program to interact with physical components. This project helped me understand how to develop software that responds to real-world inputs and controls hardware based on specific conditions.

### 2. What did you do particularly well?

I believe one of my strengths during this project was troubleshooting and working through technical challenges. When something did not function as expected, I worked to identify the issue by reviewing the code, checking hardware connections, and testing different solutions.

I also developed a better understanding of state machines and how they can be used to organize a program. Separating the thermostat into heating, cooling, and off states made the system easier to understand and manage.

Overall, I think I did well adapting to unfamiliar hardware and applying programming concepts to a practical project.

### 3. Where could you improve?

One area where I could improve is spending more time planning the overall program structure before beginning development. At times, I focused on getting individual components working before considering how they would interact with the entire system.

In future projects, I would create a more detailed design before writing code and test smaller components more frequently. I would also focus on improving error handling and making sure the system responds correctly to unexpected inputs.

These improvements would help make the development process more efficient and reduce the amount of troubleshooting needed later.

Several skills from this project will be useful in future computer science courses and professional opportunities.

### 6. How did you make this project maintainable, readable, and adaptable?

I worked to make the project maintainable by organizing the code into logical sections and using functions to handle specific tasks. This helped separate different responsibilities within the program and made troubleshooting easier.

I also used descriptive variable names and comments to improve readability. The state machine structure helped keep the operating logic organized by clearly defining how the thermostat should behave in each mode.

To make the system adaptable, I focused on keeping the code organized so additional features or hardware components could be incorporated in the future.

These practices are important because software should not only function correctly but should also be understandable and manageable when changes are needed.
